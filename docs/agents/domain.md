# Domain docs

This is a single-context repo. Before changing domain behavior, read the root `CONTEXT.md` and relevant decisions in `docs/adr/`. Use the glossary’s terms in issues, plans, tests, and code. If a proposed change conflicts with an ADR, call out the conflict explicitly.

The glossary defines domain language; ADRs record consequential design choices. If either is absent, continue without creating placeholder files. Add terms and decisions when they are resolved.
